# Catailor 博客：使用与设置说明

适用版本：2026 年 9 月「月下手记」改版。项目位于 `D:\Hexo`，使用 Hexo 与 Butterfly，优先优化电脑端。

- 博客：[https://catailor.github.io/](https://catailor.github.io/)
- 源码：[GitHub 仓库](https://github.com/catailor/catailor.github.io)
- 发布进度：[GitHub Actions](https://github.com/catailor/catailor.github.io/actions)

## 1. 怎样使用博客

| 功能 | 使用方式 |
| --- | --- |
| 阅读手记 | 点击首页文章标题或「阅读手记」；「翻开我的手记」滚动到文章区域 |
| 筛选文章 | 顶部「学习手记」「生活碎片」，或文章区「全部／学习／日常」按钮 |
| 查看更多 | 首页先展示 5 篇；日常筛选先展示 6 篇；「再翻几页」每次追加最多 6 篇 |
| 浏览全部文章 | 点击「归档」；个人卡片的手记、分类、标签数字也可以点击 |
| 日夜模式 | 根据访客电脑的当地时间自动切换，06:00–18:00 为白天，其余时间为夜间 |
| 临时更换模式 | 点击导航右侧月亮／太阳按钮；当前时段内保留选择，到下个 06:00 或 18:00 恢复自动模式 |
| 琪露诺 | 点击左下角「召唤琪露诺」，再次点击收起；首次召唤需要加载外部库和本地模型 |
| 阅读长文章 | 右侧目录跳转到章节；阅读助手可调字号、开启专注阅读，按 Esc 退出 |

页面保持打开时，每分钟检查一次时间；切回浏览器标签页也会检查。因此，跨过切换时间后，前台页面通常在一分钟内更新。手动选择按浏览器标签页的会话保存，在同一标签页跳转文章时继续生效。

首屏包含轻微鼠标视差、有限次数的星光动画，文章卡片有悬停和展开时的入场效果。系统启用「减少动态效果」时，首页关闭这些动画。站内搜索已启用，评论、留言板、RSS 和自动播放音乐保持关闭。

## 2. 启动本地预览

在电脑安装 Node.js 和 Git 后，用 PowerShell 打开项目目录。项目发布环境使用 Node.js 20；若更换 Node.js 主版本，先确认构建通过。

首次使用或依赖更新后：

```powershell
Set-Location D:\Hexo
npm ci
```

日常预览：

```powershell
Set-Location D:\Hexo
npm run server
```

打开 [http://localhost:4000/](http://localhost:4000/)。保持这个窗口运行，按 `Ctrl+C` 停止服务。如果提示 4000 端口被占用，先关闭原来的预览，或运行 `npm run server -- --port 4001`，再打开对应地址。

修改文章、图片或样式后刷新网页即可。修改 `_config.yml`、`_config.butterfly.yml` 或 `scripts/` 后，应停止并重新启动预览，确保新配置加载。

## 3. 新建、修改和保存文章

### 新建一篇文章

```powershell
npx hexo new post "my-new-note"
```

打开生成的 `source/_posts/my-new-note.md`，将文章开头设置为：

```yaml
---
title: 我的新手记
date: 2026-09-09 14:00:00
categories:
  - diary
tags:
  - 日常
---
```

三个横线之间是文章信息；下面写正文。日期换成实际写作日期。

- `title`：文章页与归档中的标题，可以用中文。
- `date`：发布时间，影响排序和链接。务必填写；发布后尽量不要修改。
- `categories`：分类。未单独设置首页分组时，包含 `diary` 的文章归入首页「日常」，其他文章归入「学习」。
- `tags`：标签，可写多项。分类和标签会自动汇总到对应页面。

文件名建议用简短英文和短横线。当前文章链接包含日期和文件名，因此已发布文章尽量保持文件名、日期不变。

### 写正文

```markdown
## 一个小标题

这里是一段正文，**这里是重点**。

- 第一件事
- 第二件事

[链接文字](https://example.com/)

![图片说明](/img/my-picture.webp)
```

正文图片放在 `source/img/`；网页路径从 `/img/` 开始，不要写电脑上的 `D:\...` 路径。数学公式使用行内 `$a^2+b^2=c^2$`，或单独成段的 `$$ ... $$`；写好后在预览中查看排版。

现有文章直接修改相应 Markdown 文件并保存，再预览。保存到本地并不等于发布。

### 暂时不公开的草稿

```powershell
npx hexo new draft "unfinished-note"
npm run server -- --draft
```

草稿放在 `source/_drafts/`，正常网站构建不展示。准备好后执行：

```powershell
npx hexo publish "unfinished-note"
```

注意：这是公开源码仓库，提交草稿文件后，别人仍可能在 GitHub 上看到内容。含私人内容的草稿应保存在仓库外。

## 4. 设置首页文案和文章卡片

最常用的设置文件是 [`source/_data/moonlit.yml`](../source/_data/moonlit.yml)。修改时使用空格缩进，不要用 Tab；同一层的缩进保持一致。

### 修改小站介绍

```yaml
intro: 关于学习，关于日常，也关于一点点好奇心。
notice: 把偶然想通的事情，认真记下来。
bio: 学习、记录、偶尔发呆。把日子里细小的光，收进这个角落。
featured: math.md
```

| 设置 | 页面位置 |
| --- | --- |
| `intro` | 首屏大标题下的介绍 |
| `notice` | 首屏下面的「小站便笺」 |
| `bio` | 首页右侧个人卡片简介 |
| `featured` | 置顶推荐手记的文件名，包含 `.md`；留空则不指定推荐文章 |

左上角名字与全部顶部导航在 `layout/moonlit/navigation.pug`。大标题「在月光下，记录一些小事」、GitHub 地址和「写在页边」文案位于 [`layout/moonlit/index.pug`](../layout/moonlit/index.pug)，不在这个设置文件内。Pug 依靠缩进表示结构，改文字时保留原来的缩进。

### 为新文章设置漂亮的首页卡片

在现有 `posts:` 下面添加一项，不要再新建第二个 `posts:`：

```yaml
posts:
  my-new-note.md:
    title: 值得记下来的一天
    summary: 用一两句话介绍这篇文章，让读者知道点进去会看到什么。
    kind: life
    topic: 日常记录
    cover: /img/moonlit/sunset.webp
```

| 字段 | 作用与取值 |
| --- | --- |
| `my-new-note.md` | 必须与文章文件名完全一致，包含 `.md`，注意大小写 |
| `title` | 统一显示于首页、文章页、归档和搜索；未填写时使用文章开头的 title |
| `summary` | 卡片摘要和文章页导读，建议一到两句纯文字，避免放公式或大段 Markdown |
| `kind` | `study` 表示学习，`life` 表示日常；这里的设置优先于文章分类 |
| `topic` | 卡片上的小栏目名，只用于展示，不会创建 Hexo 分类 |
| `cover` | 首页插画封面路径；不填写时生成文字与几何图形封面 |

新文章即使不添加卡片设置，也会自动出现在首页，但标题和摘要将从正文信息中获取。首页、文章页和归档共用展示标题与摘要。文章页使用纸页式标题区，不再重复放大封面。

## 5. 换图片、配色和动画

### 当前图片对应关系

| 页面用途 | 当前文件 |
| --- | --- |
| 首屏大图 | `source/img/moonlit/hero.webp` |
| 学习插画 | `source/img/moonlit/notes.webp` |
| 日常插画 | `source/img/moonlit/sunset.webp` |
| 头像 | `source/img/moonlit/avatar.webp` |

用相同文件名替换图片最方便。首屏建议使用横向大图；头像建议使用方形图。换图后刷新预览，重点查看人物裁切位置和文字是否清晰。

原始插画仍在 `source/img/` 中。若要从原图重新生成压缩图片，需要 Python 与 Pillow：

```powershell
python -m pip install Pillow
python tools/prepare-moonlit-images.py
```

脚本会覆盖上述四张 WebP，但不会修改原图。普通预览、构建和发布不需要运行它。

### 调整颜色与大图

打开 [`source/css/moonlit.css`](../source/css/moonlit.css)：

- `:root` 内是白天颜色，`[data-theme='dark']` 内是夜间颜色。
- `--moon-paper`：页面底色；`--moon-panel`：卡片底色。
- `--moon-text`：正文颜色；`--moon-muted`：辅助文字。
- `--moon-ink`、`--moon-accent`：强调色；`--moon-line`：边框色。
- `.moonlit-scene`：首屏背景图片和位置，目前没有额外降低不透明度，等效 `opacity: 1`。
- `.moonlit-wash`：图片上方的渐变遮罩，用于让右侧文字和页面过渡更清晰。
- 夜间 `.moonlit-scene` 保留原来的亮度、饱和度调整；它与额外降低图片不透明度是不同设置。

想让大图更淡，可在 `.moonlit-scene` 中加 `opacity: .8;`；恢复时删除这一项。调整裁切时修改 `center 30%` 中的百分比。不要删除右侧和底部渐变，否则文字和页面衔接可能不清楚。

卡片悬停效果、入场动画和星光动画也在这个 CSS 文件中；鼠标视差的移动幅度在 `source/js/moonlit.js` 的 `--scene-x`、`--scene-y` 设置附近。

## 6. 设置自动日夜模式

打开 [`source/js/theme-clock.js`](../source/js/theme-clock.js)，修改：

```javascript
const DAY_START = 6;
const NIGHT_START = 18;
```

例如改成 `7` 和 `19`，就是当地时间 07:00–19:00 白天，其他时间夜间。使用整数小时，并保持 `0 <= DAY_START < NIGHT_START <= 23`。

`_config.butterfly.yml` 中的 `display_mode: light` 是默认外观；页面会在显示正文前，根据时钟决定实际外观。该文件中 `darkmode.autoChangeMode` 保持 `false`，因为自动切换由上述脚本统一处理，不使用主题自带的 `start`、`end`。保留 `darkmode.enable: true` 和 `button: true`，让手动按钮正常工作。

旧版保存的长期日夜偏好不会阻止时钟切换。手动切换只覆盖当前时段，不能通过修改 `display_mode` 强制所有访客始终使用白天。

## 8. 更新发布到线上

当前流程：本地修改 → 本地预览 → 构建 → 提交并推送 `main` → GitHub Actions 生成 `gh-pages` → GitHub Pages 更新网站。

在项目目录执行：

```powershell
npm run build
git status
git diff
```

确认改动都是准备发布的内容后，选择要发布的文件。下面以修改一篇文章和它的首页卡片为例：

```powershell
git add source/_posts/my-new-note.md source/_data/moonlit.yml
git commit -m "Update blog note"
git push origin main
```

如果改的是样式或图片，把相应文件一并加入；新增文件也要提交。不要不看改动就把整个文件夹全部提交。

打开 [Actions](https://github.com/catailor/catailor.github.io/actions)，查看本次 `Deploy Hexo` 是否完成，再等待 Pages 更新并打开网站检查。检查最新文章、首页样式和图片是否都已更新；旧页面可按 `Ctrl+F5` 强制刷新。

`npm run build` 和 `npm run server` 只作用于本地。当前没有配置 Hexo deploy 插件，`npm run deploy` 不是本项目的上线入口；使用推送 `main` 触发的自动发布流程。

## 9. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 本地改配置后没有变化 | 停止并重启预览，再刷新页面 |
| 展示标题与 Markdown 标题不同 | `moonlit.yml` 中的标题覆盖各页面显示，未配置才使用文章的 `title`；修改后重新构建 |
| 新文章不在想要的筛选中 | 检查 `posts` 下对应文件名、`kind`，以及文章的 `diary` 分类 |
| 图片没有显示 | 检查图片是否放进 `source/`、是否已提交，网页路径和大小写是否正确 |
| 白天仍显示夜间 | 检查电脑时间、是否在当前时段内手动切换过；可以点右上角按钮切回 |
| 琪露诺未出现 | 先收起再召唤，检查外部库网络是否可用；关闭窗口会释放加载的模型 |
| 公式显示不正常 | 检查公式分隔符和语法，在本地文章页确认；暂不要同时调整多个 Markdown 渲染插件 |
| 本地正常，线上没更新 | 查看 Actions 和 Pages 发布是否成功，确认修改及图片已经提交并推送 |
| 重新生成仍有旧内容 | 停止预览后运行 `npm run clean`，再运行 `npm run build`；这只清理生成缓存，不删除文章 |

升级 Butterfly 前先保留当前可用版本。首页引用主题的公共模板，升级后应检查首页、文章页、目录、公式及日夜模式。

## 10. 搜索、专题和相关文章

### 站内搜索

点击顶部「搜索」，或在非输入框区域按 `/`。可以搜索公开文章的标题、正文、分类和标签；多个关键词用空格分开，结果需要同时匹配这些关键词。标题匹配优先于正文，命中的文字会高亮。

搜索地址可以直接分享，例如 `/search/?q=Q-learning`。每次发布都会重新生成索引，无须手动维护；私人手记从不进入索引。搜索在浏览器中完成，不会把搜索词发送给第三方搜索服务。

### 学习专题

打开 `source/_data/notebook.yml`，在 `series` 列表中添加：

```yaml
series:
  - id: reinforcement-learning
    title: 强化学习入门
    description: 按顺序理解状态、价值、策略和更新公式。
    posts:
      - MDP.md
      - Q-learning.md
      - course.md
```

`id` 使用小写英文、数字和短横线，形成 `/topics/reinforcement-learning/` 地址。`posts` 的排列顺序就是阅读顺序；文件名必须真实存在且大小写完全一致。一篇文章可以加入多个专题。专题总览在 `/topics/`，内页「探索」菜单也能进入。

已按现有笔记整理了「数学基础」「强化学习入门」「算法小札」三个专题，并新增了按分类自动收录的「日语学习日记」。文章末尾会列出所属专题的文章，并标记当前正在读的篇目。

### 手动关联

同一文件中的 `related` 用文章文件名配置：

```yaml
related:
  MDP.md:
    - math.md
    - Q-learning.md
```

这会在 MDP 文章末尾的「接下来可以读」中显示两篇文章。关联是单向的，若希望互相关联，要在另一篇下面也配置。不存在的文章会导致构建失败，避免上线后出现无效链接。主题原来的自动相关文章已关闭。

## 11. 字数、阅读时间和阅读位置

首页卡片和文章开头自动显示字数及预计阅读时间。中文和日文按汉字、假名计数，英文按词计数；估算采用每分钟 350 个中日文字符、220 个英文词，最低显示 1 分钟。这是参考值，推导公式和思考的实际时间可能更长。

阅读时顶部有细进度条，文章开头也有百分比。浏览器会保存公开文章的阅读位置；下次回来时，若上次读到 5%–95% 之间，显示「继续上次阅读」与「从头阅读」。文章字数发生变化后不恢复旧位置，带章节锚点的链接优先跳到指定章节。

位置仅保存在当前浏览器本机，不跨设备同步，也不发送到后台。私人手记不使用这个位置记录功能。

## 12. 关于我、友链、碎碎念和随机漫游

- `/about/`：个人介绍；文字在 `notebook.yml` 的 `about.intro` 和 `about.paragraphs` 中修改。
- `/friends/`：友链；尚未填入朋友时显示空状态，不自动添加陌生网站。
- `/moments/`：短动态时间线；内容按日期从新到旧排列，支持普通文字和换行。
- `/random/`：点击「带我随便逛逛」随机打开一篇公开文章。

友链与碎碎念配置示例（替换现有空列表，不要重复添加同名顶层字段）：

```yaml
friends:
  - name: 朋友的博客
    url: https://example.com/
    description: 一句话介绍这个小站。

moments:
  - date: '2026-09-10 20:30'
    text: |
      今天想通了一点小问题。
      先记下来，慢慢整理。
    tag: 学习日常
```

日期建议用引号包住并保持 `YYYY-MM-DD HH:mm` 格式。友链只接受 `http://` 或 `https://` 地址。碎碎念是公开内容；私人片段请写到下面的加密手记中。

## 13. 私人文章：本机写作，密码解锁

私人手记入口是 `/private/`。当前已用你指定的密码初始化手记本，尚未添加文章，直接解锁即可开始写作。密码不记录在项目或本文档中，也没有通用密码或找回密码功能。下面的创建步骤适用于没有 `source/private/vault.json` 的全新手记本。

### 第一次写私人文章

```powershell
Set-Location D:\Hexo
npm run private
```

用浏览器打开 [http://127.0.0.1:4002/](http://127.0.0.1:4002/)，不要把这个本机服务开放到公网。

1. 设置至少 12 个字符的独立长密码，再确认一次。建议使用密码管理器生成并保存更长的随机密码。
2. 点击「新手记」，输入标题、日期、Markdown 正文。
3. 点击「加密保存到本机项目」。标题、日期和正文在浏览器内一起加密，服务器只接收加密数据。
4. 本机项目生成 `source/private/vault.json`。它是密文，可以随博客发布；不要把明文另存进 `source/`。
5. 按通常步骤构建并发布。线上打开「私人手记」，输入同一个密码即可阅读。

日后继续编辑：运行同一命令，解锁已有手记本，选择文章点击「编辑这篇」。保存只更新本机密文，推送并发布后线上才会变化。

```powershell
npm run build
git add source/private/vault.json
git commit -m "Update encrypted private notes"
git push origin main
```

### 阅读、锁定、备份

解锁过程完全在浏览器内完成，不把密码提交给网站。解锁页不加载统计脚本或看板娘。点击「锁定」清除页面中的正文和密码；离开页面会锁定，没有未保存编辑时，闲置 5 分钟也会锁定。正在编辑且未保存时，为避免丢稿，不自动锁定，请离开电脑前先保存并手动锁定。

本机写作入口的「备份与修改密码」可下载加密备份、重新设置密码。每次覆盖保存时，还会将上一份密文备份到项目的 `.private-backups/`，这个目录不会提交到 GitHub。需要恢复备份时，先停止本机写作服务，将选中的加密备份复制为 `source/private/vault.json`，重新打开并使用该备份对应的密码解锁。

### 边界与注意事项

- 这是密码加密，不是身份登录。只有持有正确密码的人能解密，因此不要分享密码；忘记密码无法恢复内容。
- 加密采用 PBKDF2-SHA256（600,000 次迭代）和 AES-GCM-256，每次保存使用新随机盐和随机 IV。密码强度仍然重要，因为密文可以被公开下载。
- **不要把私人明文放到 `source/_posts/`、`source/_drafts/`、`source/_data/` 或公开图片目录。** 公开仓库的源文件也会被别人看到。私人草稿可放到仓库外，或已忽略的根目录 `private-drafts/`。
- 构建会拒绝 `private: true`、`password:` 标记的普通文章，以及 `source/private/` 里的明文文件；这些标记不会自动帮你加密。
- 暂不支持私人图片附件或原始 HTML，Markdown 图片不会加载，避免将私人附件误当作公开资源。标题、段落、列表、代码和普通链接可以使用；数学公式暂按原始文本展示。
- 删除文章或修改密码不会抹去已经公开过的旧版本密文；已公开过的明文文章，也不能靠以后加密就收回他人已经保存的内容。
- 多个编辑窗口同时保存时会检查文件版本，避免悄悄覆盖。若提示冲突，先把未保存文字临时留在仓库外，再刷新并重新编辑。

## 14. 新版构建与维护

## 15. 统一的纸页样式与阅读助手

文章、归档、标签、分类及公开小页面现在共用导航、纸张色、宋体标题、月亮标记和页尾落款；日夜模式仍按访客当地时间自动切换。

- **文章排版**：正文默认 18px，段落增加留白，引用、代码、表格和独立公式分别处理；长代码、长公式可在各自区域横向滚动。
- **字号**：右侧「按自己的节奏读」提供小 / 标准 / 大（16 / 18 / 20px），选择保存在当前浏览器，下次阅读继续使用。
- **专注阅读**：隐藏导航、侧栏和看板娘，保留正文；点击「退出专注」或按 Esc 返回。切换字号和专注状态时尽量保持当前段落的位置。
- **目录**：缺少跳转地址的标题会在生成时自动补齐，已有地址保留。点击章节会避开顶部导航，地址栏带上章节链接，方便分享。
- **阅读进度**：保留顶部细线和续读提示，右下方新增当前百分比及剩余阅读时间。预计时间仅作参考。
- **文章末尾**：统一作者签名、许可说明、标签、关联阅读和前后篇入口，可点击复制当前页面链接。
- **归档**：按年份和日期排列，不再显示重复缩略图；原有年月归档、标签、分类与分页地址继续可用。
- **小页面**：关于我、专题、搜索、碎碎念、友链、随机漫游、标签及分类采用同一套风格；`source/404.md` 定制了走丢页面。

### 封面不必每篇都用插画

首页保留主视觉插画，以及数学笔记、3/30 日记的两张独立插画封面。其他卡片使用六种柔和的图形背景，并配合栏目、日期和符号区分。默认样式根据文件名稳定分配，刷新不会随机改变。

在 `source/_data/moonlit.yml` 对应文章下添加 `cover` 可以指定图片；删除 `cover` 或填写 `cover: false` 使用图形封面。还可以加 `symbol: '☾'` 自定义卡片与文章标题区的符号，建议仅填一个符号。

| 内页公共结构和页尾落款 | `layout/moonlit/interior.pug` |
| 文章标题、作者落款与相邻手记 | `layout/moonlit/post.pug` |

## 16. 日语学习专栏

专栏入口为 `/topics/japanese/`。每天运行 `npm run japanese`，填写生成的学习日记，再按原流程发布即可。带有 `日语学习` 分类的文章会自动加入专栏，最新在前，不需要逐篇修改专题清单。

模板包括今日学习、词语与假名、例句、语法、听读练习及复习计划。同一天重复新建不会覆盖已有内容。完整步骤见 [日语学习专栏说明](日语学习专栏.md)。
