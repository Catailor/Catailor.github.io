### Genie 2024.02
1. **问题**：能否仅从无标注互联网视频中，无监督地学出一个可逐帧控制、可由文本/图像/草图提示生成的交互式虚拟世界，而不需要真实动作标签或领域特定数据。
2. **方法**：Genie 用三组件——ST-transformer 视频 tokenizer 把视频压成离散 token，Latent Action Model 从相邻帧无监督推断 8 个离散潜在动作，MaskGIT 动力学模型根据过去 token 和潜在动作自回归预测下一帧；推理时用户输入替代潜在动作。
3. **遗留问题**：只有 16 帧记忆，长时一致性差，会幻觉不真实未来；约 1 FPS，远未实时；主要验证 2D 平台游戏和机器人视频；未发布模型权重与训练数据，通用性仍待证明。
4. **为什么可信**：在约 3 万小时平台游戏视频上训练出约 11B 模型，能对 Imagen2 生成图、手绘草图、真实照片等 OOD 提示产生可控轨迹；在 RT-1 机器人视频上 FVD 82.7；在 CoinRun 上仅 200 个专家样本就达到 oracle 行为克隆水平；消融也显示 ST-ViViT 和像素输入 LAM 更优。
5. **与我何关**：它指向“提示即游戏/世界”的范式——任何人都能用草图或照片生成可玩世界，并为机器人、智能体训练提供从互联网视频学习潜在动作和世界模型的路径；但当前仍是研究原型，不能实时替代游戏引擎。

### GameNGen 2025.04
1. **问题**：能否用一个神经网络完全替代传统游戏引擎，在实时交互中高质量、长时间稳定地模拟复杂游戏 DOOM。  
2. **方法**：先训练 RL 智能体玩 DOOM 收集动作—画面对，再用改造自 Stable Diffusion v1.4 的扩散模型根据过去 64 帧和动作预测下一帧，并用噪声增强防漂移、微调解码器提细节、4 步 DDIM 实现 20 FPS。  
3. **遗留问题**：模型只有约 3 秒记忆、智能体行为与人类有偏差、不能轻松创造新游戏、不是精确模拟器，且尚未在消费级硬件验证。  
4. **为什么可信**：单帧 PSNR 约 29.4 接近有损 JPEG，人类区分模拟与真游戏接近随机（50%–60%），单 TPU 上 20 FPS 稳定多分钟，消融实验也证明噪声增强等关键设计有效。  
5. **与我何关**：它预示游戏可能从人工代码变成神经模型权重，让实时生成式交互世界、AI 自动生成游戏内容成为可能，但短期仍是概念验证，不能替代 Unity/Unreal 或直接用于产品。

### Matrix-Game 2025.06
1. **问题**：如何用视频扩散模型构建一个可交互的游戏世界基础模型，既能高画质生成，又能精确响应键盘/鼠标动作，还符合游戏物理规则，并且有统一基准可评估。
2. **方法**：Matrix-Game 采用两阶段训练——先在大规模无标签 Minecraft 视频上预训练世界理解，再用动作标注数据训练交互式生成；模型是 17B 参数的扩散 Transformer，基于 3D Causal VAE 潜空间，条件于参考图、运动上下文和用户动作，支持自回归长视频生成。
3. **数据**：构建 Matrix-Game-MC，包含 2700+ 小时无标签 Minecraft 视频和 1000+ 小时高质量动作标注视频，标注含细粒度键盘和鼠标动作；另用 Unreal Engine 程序化生成补充数据。
4. **评估**：提出 GameWorld Score 统一基准，从视觉质量、时序质量、动作可控性、物理规则理解四个维度评估；Matrix-Game 在 8 个子指标上全面优于 Oasis 和 MineWorld，双盲人类评估也大幅胜出。
5. **意义与局限**：它把“图像到世界”生成推向可交互、可控制、可评估的新阶段，并开源模型权重和基准；但仍在边缘场景泛化、物理理解（如穿过树叶）、长期时序一致性、动作空间丰富度上有局限。

### Matrix-Game 2.0 2025.08
1. **问题**：现有交互式世界模型依赖双向注意力和大量去噪步数，推理慢、延迟高，无法根据用户实时动作流式生成视频。
2. **方法**：Matrix-Game 2.0 用少步自回归扩散 + Self-Forcing 蒸馏，把双向基础模型变成因果学生模型，支持 KV 缓存和流式生成；动作模块注入逐帧键盘和鼠标信号。
3. **数据**：构建 Unreal Engine 和 GTA5 数据生产管线，生成约 1200 小时带动作标注的视频，解决动作—画面对齐和动态交互建模问题。
4. **结果**：单张 H100 上以 **25 FPS** 生成分钟级高质量视频，在 Minecraft 和 wild scenes 上优于 Oasis、YUME，可控性和视觉质量大幅领先。
5. **局限**：OOD 场景会过饱和或退化，输出分辨率仅 352×640，长期历史一致性仍缺显式记忆机制；但模型权重和代码已开源。

### Matrix-Game 3.0 2026.04
1. **问题**：现有交互式世界模型无法同时满足长期记忆一致性、高分辨率保真和真正实时交互；2.0 实时但没记忆，Lingbot-World 有记忆但难实时。
2. **方法**：Matrix-Game 3.0 在 2.0 基础上加入错误感知训练、相机感知记忆检索与注入、训练-推理对齐的多段 DMD 蒸馏，以及 INT8 量化、VAE 剪枝、GPU 检索等实时加速。
3. **数据**：升级工业级数据引擎——Unreal Engine 5 合成管线 + 多个 AAA 游戏自动录制 + 真实世界视频，产出大规模 Video-Pose-Action-Prompt 四元组数据。
4. **结果**：5B 模型在 720p 下达到 **40 FPS**，分钟级序列保持稳定记忆一致性；扩展到 **2×14B MoE** 后生成质量、动态性和泛化进一步提升。
5. **意义与局限**：它提供了工业级可部署世界模型的实践路径，但分辨率、长期依赖建模、复杂交互仍有提升空间。
